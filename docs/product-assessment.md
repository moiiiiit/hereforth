# Is Hereforth worth building as a standalone app?

November 20, 2026

**Yes to a standalone Mac service. The broad feature set gives it a weak competitive advantage today.** A person who works across multiple assistants has a reason to install Hereforth even if nobody else joins. They can ask “Where did I leave this, and why did we decide that?” from their current assistant. Sharing becomes valuable when a colleague can pick up the work without interrupting them. Small teams that regularly switch between tools and hand work across time zones are the first audience I would test.

The Mac earns its place by holding private source material, remembering corrections across providers, and enforcing what leaves the device. The everyday interface can stay in Claude, ChatGPT, or Cursor. A teammate should be able to follow an invitation and ask from their existing assistant before deciding whether to install Hereforth on their own computer. That onboarding flow and the quality of the answers are still untested.

## Where competitors already meet the brief

| User promise | What someone can choose today |
| --- | --- |
| Ask a coworker's agent while they are busy | Comity documents a paid feature that runs a read-only copy of the owner's recent agent session on their machine. It also documents context handoffs and routing questions to a human with the answer returned to the agent. Alook describes an open-source alternative for coworkers using Codex or Claude Code. [Comity Q&A](https://comity.so/docs/collaboration/ask-my-agent) · [Handoffs](https://comity.so/docs/collaboration/handoffs) · [Human replies](https://comity.so/docs/collaboration/needs-a-human) · [Alook](https://alook.ai/blog/ask-coworker-codex-claude-code) |
| Ask Claude for the team standup | Contextingo already documents this exact prompt in Claude Code and Codex. It returns each member's progress, blockers, and reviews from saved project records. Cursor Multiplayer Projects offers shared context and lets one coordinator ask another's agent directly. Teams already standardized on Cursor have a clear reason to try that first. [Contextingo standup](https://contextingo.com/guides/catch-up-standup-claude-code) · [Cursor Projects](https://cursor.com/docs/agent/projects) |
| Have a personal assistant that follows work across channels and shares selectively | OpenAI dots carry context across ChatGPT, Slack, and Teams. Indalbo describes per-person assistants that answer according to their owner's sharing rules and give them a receipt. An always-on assistant, sharing controls, and a transcript of disclosures each have precedents. [OpenAI dots](https://openai.com/index/introducing-dots/) · [Indalbo](https://indalbo.com/) |
| Move an old conversation into another tool | Skillsync already searches and continues sessions across supported tools using the open-source txcript library. Its compatibility table distinguishes sources it can read from destinations it can resume. It is a candidate dependency and a baseline for the personal experience. [Session compatibility](https://api.skillsync.com/docs/transcript-support) |

These are documented capabilities. Comparative accuracy, adoption, and willingness to pay would require hands-on pilots. The plausible long-term advantage is becoming the place a team trusts to recover the *current* answer across tools. Each confirmed decision, correction, and source link can improve the next handoff. That advantage takes repeated use to earn. Open formats let people keep that history and lower the risk of entrusting their work to a new project.

## What people asked for, and what I would build

1. **A handoff the next person can actually resume.** A Cursor user wanted to take over a teammate's chat. Separately, a Claude user asked to preview and move just one topic's facts, corrections, and open questions into ChatGPT. Combine those requests in one trial. Mohit asks “Hand the launch migration to Priya.” He previews the shareable decision, failed approach, relevant PR, and next step. Priya opens the brief in her chosen assistant, accepts it, and can start with the outstanding question. Export it as ordinary Markdown so the handoff still works for a colleague who has never installed Hereforth. Measure time to the recipient's first useful action and whether they had to ask Mohit for context. [Cursor team request](https://forum.cursor.com/t/teams-share-same-chat-sessions-to-work-collaborate/161432) · [Claude selective-export request](https://github.com/anthropics/claude-code/issues/107332)
2. **Answer “Which decision still stands?” with the exact passages.** One ChatGPT user wanted retrieval when they remembered an idea but had forgotten the wording. Another explicitly asked for later revisions and superseding decisions. A Cursor user described reopening chats on the wrong Git branch and asked for branch and merge awareness. Extend Hereforth's existing citations with a history a person can correct. Start with one meeting decision, a later chat correction, and read-only PR status. Let the owner ask “What changed?” and give each teammate the latest evidence they can read. If a private revision invalidates a shared answer, withdraw the stale answer and let the owner publish a replacement. [Search by meaning](https://community.openai.com/t/account-wide-semantic-search-and-retrieval-across-chatgpt-history/1395849) · [Request for revision-aware retrieval](https://community.openai.com/t/feature-request-user-initiated-conversation-history-retrieval/1396965) · [Cursor branch request](https://forum.cursor.com/t/associate-local-agent-chats-with-git-branch-they-were-started-from/153093)
3. **Make “Who needs me?” work in both directions.** Engineers who tried async standups reported that blockers sat unanswered in chat. Give a blocker a named recipient, a concrete question, and a way to acknowledge, answer, or request a conversation from their own assistant. Deliver the decision back to the requester and update the next standup. Use a short meeting for the issues that still need discussion. This is a test of whether Hereforth can remove coordination work. Comity already documents much of the mechanism. [Practitioner's account](https://www.reddit.com/r/cscareerquestions/comments/111k0uj/why_wouldnt_you_do_standup_async/) · [Mixed experiences with async standups](https://news.ycombinator.com/item?id=29677684) · [Comity human replies](https://comity.so/docs/collaboration/needs-a-human)

4. **Let me follow one answer.** After asking “Are we still launching Thursday?”, Priya can say “Tell me if that changes.” Recheck when an approved launch decision changes. Notify her once, with the new date and a citation she can open, then let her mute or expire the watch. A Confluence user asked for notifications limited to a particular part of a page. Following an answer across tools is my extension of that request. Prototype it for one decision before introducing general-purpose alerts. [Confluence user's request](https://community.atlassian.com/forums/Confluence-questions/Notification-on-a-part-of-a-page/qaq-p/730084)

A trust issue cuts across these features. One Cursor user reported that a fresh project chat recalled another project's conversation. Give the owner an easy way to ask “What would Priya see about this?” and to exclude a project from general recall. Test with two similarly named projects and a mixed personal/work transcript. The existing grant experiment covers retrieval for two viewers. The next test is whether a real person can predict the answer before sharing. [Cursor user's report](https://forum.cursor.com/t/new-chats-are-using-context-from-previous-projects/170749) · [Hereforth sharing design](teammate-knowledge.md)

## Scope and a decision after four weeks

Keep personal recall, a single handoff, and the team standup query in the first pilot. Use one source from a meeting or personal chat and one from a coding tool, plus a read-only GitHub PR from the same task. Let the caller's assistant phrase the result from approved excerpts. That gives the pilot a path without using the owner's consumer subscription to serve the team. Keep timestamps and source attribution visible, especially when an agent is running but its human owner has posted no update.

Use basic usage receipts and a task-duration awake timer where they help the pilot. Richer power schedules, universal desktop control, IT provisioning, more connectors, and a 200k-token target can wait for a specific workflow that needs them. If laptop downtime spoils handoffs, trial an optional team host for owner-published briefs with timestamps, expiry, and a grant check on every read. Keep private transcripts on the Mac and let the owner revoke on the online host. [Availability and usage plan](availability-and-usage.md) · [Owner remote control](remote-control.md)

Recruit three small teams using at least two assistants. For one week record actual handoffs, clarification DMs, blocker wait times, and time spent in one recurring sync. For the next three weeks let them use Hereforth on the same work. Compare at least one matched handoff with their current shared-chat or PR workflow and one with the closest competing tool. Include a question whose answer changed, a recipient with narrower access, and an owner who is away.

I would fund the next milestone if, in at least two teams, two teammates use it again unprompted on separate days, a handoff reaches the next useful action with fewer clarification messages, and the organizer shortens or skips a real sync with net time saved after preparation and follow-up. Ask the budget holder to continue on a paid pilot to test the business case. A wrong-audience disclosure stops the sharing trial. If people repeatedly use personal recall but colleagues stick with shared links, narrow the product to the private cross-assistant Mac utility. These are proposed decision thresholds, not observed results.
